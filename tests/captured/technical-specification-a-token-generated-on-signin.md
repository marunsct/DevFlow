## Domain Model
- Account: Identified by integer `id`. Attributes: `username` (unique string, non-empty), `password_hash` (string, bcrypt-hashed). Created via POST /signup. Validated for uniqueness and non-empty username.
- Item: Identified by integer `id`. Attributes: `title` (string, non-empty), `done` (boolean, defaults to false), `account_id` (integer, foreign key to Account.id). Owned by the Account associated with the authentication token used to create it. Created via POST /items, listed via GET /items, toggled via PATCH /items/{id}, deleted via DELETE /items/{id}.
- Token: Opaque string identifier for an authenticated session. Generated on successful signin (POST /signin). Persisted in the SQLite `tokens` table keyed by its SHA-256 hash, mapping to a single Account.id. No expiration defined. Used as Bearer token in Authorization header.
- Secret Key: Cryptographically random 32-byte hex string generated once at first startup. Stored in `DATA_DIR/secret.key` with permissions 0o600. Used for HMAC signing if required (though brief implies opaque tokens, secret key is kept for potential future extensibility or internal integrity as per security specialist advice SR-1 and BE-8).
- Database: SQLite file located at `$DATA_DIR/tasks.db`. Tables: `accounts` (id, username, password_hash), `items` (id, account_id, title, done), `tokens` (token_hash TEXT PRIMARY KEY, user_id INTEGER NOT NULL). Schema initialized on startup if missing or invalid.
