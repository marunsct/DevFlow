- POST /notes or PUT /notes/{id} with a body that cannot be parsed as JSON (including multipart, form-encoded or file-bearing requests, which the service does not accept) -> 400 with exactly {"error":"invalid JSON body"}; nothing is stored or changed.
- POST /notes or PUT /notes/{id} with valid JSON that is not an object (an array, a string, a number, a boolean or null) -> 400 with exactly {"error":"request body must be a JSON object"}; nothing is stored or changed.
- POST /notes or PUT /notes/{id} with a title that is missing, null, a non-string, or empty or whitespace-only once trimmed -> 422 with exactly {"error":"title is required and must be a non-empty string"}; nothing is stored or changed (an empty or whitespace-only title is refused exactly as a missing one).
- POST /notes or PUT /notes/{id} with a body that is present but not a string -> 422 with exactly {"error":"body must be a string"}; nothing is stored or changed (an omitted body is accepted and stored as "" and is not an error).
- GET /notes/{id}, PUT /notes/{id} or DELETE /notes/{id} with an id segment that is not a positive integer (non-numeric, non-integer, 0 or negative) -> 404 with exactly {"error":"note not found"}; nothing is changed (on PUT, validation runs before any lookup, so a malformed body is refused with 400/422 even for a non-integer id).
- GET /notes/{id} with an id that does not exist (including one already deleted) -> 404 with exactly {"error":"note not found"}; nothing is changed.
- PUT /notes/{id} with a valid body for an id that does not exist -> 404 with exactly {"error":"note not found"}; the store is left unchanged.
- DELETE /notes/{id} with an id that does not exist, or an id that was already deleted -> 404 with exactly {"error":"note not found"}; no row is removed and the id is never answered 204 twice.
